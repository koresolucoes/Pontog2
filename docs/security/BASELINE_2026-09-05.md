## Privileged RPC ACL/definition baseline
The following functions are `SECURITY DEFINER` and at capture have EXECUTE ACLs including PUBLIC/anon/authenticated/service_role:
- `get_all_users_for_admin()`
- `grant_album_access(integer, uuid)`
- `get_or_create_conversation(uuid, uuid)`
- `mark_messages_as_read(integer[])`

### Authorization defects to preserve only for rollback reference
- `get_all_users_for_admin()` has no caller/admin check.
- `grant_album_access()` compares owner using `!= auth.uid()` and can fail open for NULL auth.
- `get_or_create_conversation()` does not require caller to be either participant.
- `mark_messages_as_read()` does not prove conversation membership/recipient.

## Rollback discipline
This file describes the insecure baseline so it can be restored only as an emergency compatibility rollback while a safer fix is prepared. It must **not** be treated as a desired security configuration.

For every change:
1. Save forward SQL/code.
2. Save exact inverse before apply.
3. Do not delete user data during containment.
4. Do not mix policy changes and destructive cleanup in one migration.
5. Verify anon, user A, user B and authorized backend separately.
6. Vercel rollback returns to a known READY deployment; database rollback uses the inverse migration for that exact stage.
